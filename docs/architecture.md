# Design and architecture

The Windows application is native WinUI 3. There is no web view, Electron shell, WPF host, macOS theme, Dynamic Island or Liquid Glass implementation.

## Windows shell

`TrayIcon` uses documented `Shell_NotifyIcon` APIs, a stable icon GUID, version 4 selection callbacks and keyboard activation. It recreates the notification icon after Explorer restarts. The compact window is hidden from Alt+Tab/taskbar switching and lives beside its tray icon, constrained to the current monitor's work area. Closing it hides the window. Right-click offers Open, Settings and Exit. A per-session named mutex and activation event make a second launch open the existing process.

The process normally runs as the signed-in user. No administrator privileges, services, drivers or shell injection are installed. Global hotkey conflicts produce a visible warning. Windows can place the icon in overflow; the app does not force a registry preference to pin it.

Reopening explicitly restores minimized windows. The resident process publishes its process ID through a session-local memory mapping; a second launch grants foreground activation to that process before signaling the activation event. This follows Windows' [foreground activation rules](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-allowsetforegroundwindow) and uses [SW_RESTORE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow) to recover after Show desktop.

## Materials and controls

Main, settings, onboarding and tool windows receive `Microsoft.UI.Xaml.Media.MicaBackdrop`. The temporary shelf drop receiver uses a transparent composition backdrop so its inset cue can sit over the real taskbar icon without a second material or native frame. Mica supplies wallpaper-tinted material and system fallbacks, including inactive, transparency-disabled and high-contrast behavior. It is not live glass transparency. Resource-based brushes follow Windows theme and contrast settings. No backdrop simulation or custom blur shader is included.

The Fluent resource dictionary sets the Segoe UI Variable control font, 8-pixel cards/control corners and 4-pixel small-check geometry. Headers use the Windows `TitleTextBlockStyle` ramp; body labels and captions use its native text styles. The main surface uses a two-column tool grid, and Settings uses a modular feature grid with native toggles. NavigationView, ContentDialog, native pickers, InfoBar, NumberBox and default focus/keyboard visuals carry the settings experience. Layouts scroll when content grows. Per-monitor DPI is declared in the manifest and used for placement; mixed-DPI rendering still requires Windows validation.

## Availability and services

`Vela.Core.FeatureCatalog` is an allowlist containing only implemented extra capabilities. `AppSettings.Normalize` discards native/unknown feature IDs during import. The JSON audit is intentionally broader than the runtime catalog: it records everything examined and all missing residuals.

`FeatureRuntime` creates resident services only for enabled features and stops/disposes them when availability changes. On-demand tools have no resident service. Clipboard features share one listener, and input tools share keyboard/mouse hooks with independent availability. Turning off the last dependent feature detaches the shared infrastructure. Onboarding does not start selected background services until completion. Most settings do not restart already-running services.

`AwakeService` runs on the UI dispatcher because `SetThreadExecutionState` is thread-scoped. Its timer/app/AC requests are released on disable or exit; Windows retains ownership of explicit sleep and lid actions. Dimming uses per-monitor click-through Win32 overlays, and removes all overlays on disable, topology change and exit.

## Data boundaries

Settings are written through a temporary file and same-filesystem replacement. An unreadable existing settings file is preserved with a recovery copy when possible. Schema version, enum-like values, bounded numeric settings, allowed feature IDs, snippets and shortcuts are checked on import. Sign-in registration is not imported.

Automatic link cleanup only rewrites clipboard data whose advertised format is plain text. It checks clipboard ownership after asynchronous reads, retains all non-tracking bytes of a link's query, and leaves known signed links intact. Auto-clear only manages the current clipboard; it does not claim to erase Windows history or copies held by other processes.

The shelf holds explicit user drops in memory. Conversion creates new files with unique names; source images are not edited. Input tools keep only a short in-memory trigger buffer and do not log keystrokes. While a snippet prepares a paste, subsequent physical events are briefly buffered in memory and replayed in order; preparation has an eight-second cancellation bound. Snippet expansion skips Vela’s own windows. It rechecks foreground, focus, exclusions, standard password state and feature/session availability after preparing clipboard providers. All advertised formats are materialized before editing; an unsupported or busy provider leaves the typed prefix intact. Deletion, one paste and exactly one delimiter precede paced FIFO replay of buffered physical input. A trigger completed during replay hands the remaining queue to the next replacement. Physical completing keys and replayed completing keys are tracked independently, so a queued release cannot suppress a later physical delimiter. Clicking another destination, session lock/suspend, cleaning or shutdown drops pending input and releases synthesized paste modifiers plus keys whose downs were already replayed. A bounded asynchronous-state check confirms Control before paste and its release before FIFO replay. Session notification registration is independent of clipboard-feature selection. The clipboard is restored only if its sequence still identifies Vela's temporary text, so a newer copy or session clear wins. Clipboard transfers are serialized with plain paste and are tracked during shutdown. No clipboard watcher is needed for snippet variables. Per-app exclusions are available; elevated processes, secure desktops, IME composition and custom editors require compatibility checks. Hardware fan writes, audio amplification and app-leftover deletion are absent until their additional backends and validation exist.

Shelf entries use reference identity so a late drag completion cannot remove a newer identical entry. Only an accepted Copy can remove transferred entries. A renewable cancellation scope stops delayed providers before collection mutation on disable, lock, suspend and shutdown; shelf tool lifetime cancellation also covers close. The accepted five-file drop receiver remains unchanged.

An explicit `--data-directory` validation profile isolates settings and startup-error diagnostics, rejects the normal data folder and disables sign-in registration changes. It shares the one-instance guard; testing requires the resident instance to exit first. Without that option the normal data path and startup behavior remain unchanged. `--settings` opens General directly after completed onboarding on a fresh launch.

## Additional local workflows

Command search parses bounded UI input into literal AND terms, preserving quoted phrases and incomplete quotes while typing. Each term matches a command's name, category or explicit keywords; phrases stay within one field. Exact names and prefixes rank before contained/reordered names and metadata, with stable ties and unchanged blank-query order. Saved launcher targets are searchable without opening or enumerating them. The native ListView retains selection/invocation behavior ([Microsoft guidance](https://learn.microsoft.com/en-us/windows/uwp/controls-and-patterns/listview-and-gridview)); its viewport adapts to the tool scroll area so query-focused arrow selection remains visible. A single current resize callback is replaced when profile editing rebuilds the command UI, rather than accumulating handlers for removed editors.

Launcher profiles preserve legacy flat entries and add bounded submenu trees: eight siblings per menu, three levels and 64 total entries per profile. Normalization copies each tree, rejects unsafe leaf targets, and never treats a group as an executable target. Command search flattens only leaves and includes their group path. The Command bar and dedicated launcher settings edit and reorder entries in place; deleting a populated submenu explains its contents in a native confirmation dialog. The radial window snapshots the selected profile, supports number keys, cyclic Up/Down selection, native Enter/Space activation, parent navigation and Escape. A small viewport uses full-size buttons in a scrollable list instead of shrinking the wheel. Managing the radial menu opens its own native settings window without enabling the Command bar. Keyboard focus follows submenu navigation; the explicit global shortcut grants the new window foreground activation. See Microsoft's [keyboard event and focus guidance](https://learn.microsoft.com/en-us/windows/apps/develop/input/keyboard-events).

Centre-drag radial selection uses a pure DIP-coordinate gesture model and WinUI pointer capture. The release position determines the sector; returning to the centre after leaving it, releasing outside, capture loss, keyboard navigation, list fallback and close cancel it. A transparent pointer host leaves the native centre button available for keyboard/automation activation. Core geometry and native compilation pass; rendered pointer/accessibility behavior remains open.

Plain paste snapshots all advertised formats before replacing the clipboard, waits for physical shortcut modifiers to be released, and restores only while it still owns the temporary clipboard sequence. A new copy or lock-time clear takes precedence. Rich data that cannot be materialized aborts the operation without replacing the original. Plain paste is tracked during clean shutdown: cancellation stops preparation, while an already submitted paste retains its 800 ms payload window before restoring. Restoration retries a refused clipboard write up to three times and rechecks ownership before each attempt; a newer copy wins. Snapshots preserve the original requested copy/move operation, limit advertised formats to 64 and bound copied bitmap streams.

Saved workspaces use documented Win32 placement APIs. Relative normal-window coordinates adapt to work areas; maximized state is stored separately, and one undo snapshot preserves full Windows placement state. Session handle/PID hints disambiguate still-open windows, with process/title matching as a fallback. Search and command results do not capture thumbnails or index files. Optional topmost pinning changes only selected ordinary windows and restores Vela-owned layers on disable/exit.

DDC/CI access is serialized off the UI thread and scopes physical-monitor handles to one operation. NVIDIA monitoring loads the installed System32 NVML library and uses read-only queries. GPU alerts identify cards by NVML UUID, with a device-index fallback; their 30-second sustained interval uses fresh monotonic samples and resets on interruption or threshold change. Resource alerts share that policy, and all alert cooldowns last 15 minutes. These adapters return capability absence in a VM; they do not infer support from a brand name. See [hardware support](hardware-support.md).

The separate x64 OCR worker uses Tesseract and a pinned English model entirely offline. Windows ARM64 launches it under x64 emulation. The worker has a cancellable process boundary and requires the Microsoft Visual C++ x64 runtime. Image/video output uses unique new filenames and installed Windows codecs. Messaging review is bounded to an explicitly selected folder, rejects reparse-point traversal, rechecks file metadata before recycling, and requires user selection plus a confirmation dialog. It has no unattended removal timer.

JPEG quality is a codec creation option, not image metadata. Optional JPEG byte limits measure bounded candidate qualities in temporary memory streams, retain a tested fitting quality, and enforce the actual final byte count before keeping an output. Dimensions are preserved unless the existing resize setting changes them. Impossible limits create no output; cancellation disposes streams and removes incomplete copies. The native regression verifies distinct quality-100/quality-10 file sizes as well as actual capped output. PNG/BMP budgets and target-size video compression remain absent. See [Microsoft's encoder options example](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/imaging).

Internet speed testing is on demand and uses the [documented Cloudflare transfer endpoints](https://github.com/cloudflare/speedtest#api-reference). Five small requests establish HTTP latency after excluding the first DNS/TLS warm-up request. Download and upload are single-connection throughput estimates, each time-bounded and byte-capped; upload counts only server-acknowledged chunks. The client disables cookies and automatic redirects, asks for uncompressed responses and bypasses caches. Only generated zero bytes are uploaded. No results-report endpoint is called, and measurements are not persisted. Window close, feature disable and exit cancel the request. Core tests use an in-memory HTTP handler and never contact an external service.

Image pins consume an explicitly requested clipboard bitmap or local file. The decoder rejects inputs over 128 MB or 100 megapixels and scales previews to a 2048-pixel longest edge before native display. At most six previews remain in memory. Each pin uses a native Mica window and [OverlappedPresenter.IsAlwaysOnTop](https://learn.microsoft.com/en-us/windows/apps/develop/ui/manage-app-windows). Closing a pin releases its image source; disabling the feature or exiting closes all pins. No capture engine, image history or file write is added.

Animated GIF batches use Windows MediaComposition frame extraction and the [built-in GIF encoder](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.imaging.bitmapencoder), with [WIC frame/container metadata](https://learn.microsoft.com/en-us/windows/win32/wic/-wic-native-image-format-metadata-queries) for timing and looping. The worker handles one frame at a time, up to 300 frames, a 1280-pixel edge, 30 seconds and a 100 MB output limit per file. It applies the selected trim to each video, writes unique filenames, removes incomplete outputs and leaves source files intact. Failed files are reported individually. Encoding runs off the UI thread; closing the tool, disabling it or choosing Cancel cancels the batch.

The shelf drop service owns temporary WinUI drop surfaces and a timer only while enabled. Its taskbar-button mode keeps a minimized shelf window and uses the accessible button under the pointer. External data is validated before collection, multi-file packages retain all selected references, and successful-transfer removal is separate from deleting originals. Cleaning sessions use a monotonic deadline, capture the mouse-lock option at start and end on timeout, continuous Escape, window close, suspension, feature disable or exit.

Clipboard preparation retries only transient clipboard-open failures against fresh all-format snapshots. Publication also handles temporary Boolean refusal. Both use bounded retries, cancellation and clipboard sequence checks, so a newer copy cancels preparation before editing. Temporary snippet/plain-paste text is published as immediately rendered CF_UNICODETEXT through a valid owner HWND. Movable global buffers are allocated before emptying the clipboard; ownership is rechecked inside the Windows clipboard lock. Registered CanIncludeInClipboardHistory and CanUploadToCloudClipboard DWORDs are zero. After close synthesizes accompanying text formats, Vela captures the resulting sequence and checks that its owner window still owns the data. Partial publication failures retain restoration ownership; a newer copy is never adopted. All-format restoration remains shared with the WinRT snapshot. See [clipboard operations](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-operations) and [clipboard formats](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats). Receiver compatibility remains subject to the desktop checks in verification.md.
