## Corrections

- A refused recovery copy previously allowed a later save to replace the only unreadable original. Save now retries preservation first and refuses replacement while the backup is denied. Distinct complete recovery copies use unique names, including successive corrupt versions within one second. A successful reload clears an obsolete recovery warning.

The settings model and schema version remain unchanged. Recovery copies preserve original bytes; this is not an automatic repair or merge of corrupt preferences.
- Settings import first normalizes an independent copy and persists it. Live settings change only after that write succeeds. A blocked commit retains the exact previous object and disk bytes. Successful import retains local onboarding state, keeps sign-in startup separate and does not alias the reviewed backup object.
- Backup reads and exports enforce a 4 MB byte limit. Reads remain bounded while consuming the file and reject malformed/future JSON or invalid UTF-8/UTF-16/UTF-32 encoding. Supported BOM files, Unicode, disabled-feature preferences and the shelf target round-trip. Oversized or canceled exports preserve the previous destination. Normal settings files retain their existing schema and size behavior; the 4 MB limit applies to backup transfers.
- Import/export work is tracked through window close and controller Exit. Pending native confirmation is dismissed, canceled work is awaited, concurrent transfers are refused and a closed/quitting window cannot admit a late import. Normal canceled work no longer becomes a startup failure log; a deliberately faulted operation still produces a diagnostic.
