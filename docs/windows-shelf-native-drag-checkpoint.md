## Change

Outgoing file drags with automatic removal enabled now give the tracked IDataObject directly to [OLE DoDragDrop](https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-dodragdrop). WinUI's original drag is canceled and native dragging starts on the dispatcher after that event. This bypasses the bridge that was not forwarding the final callback. Incoming drops, the accepted taskbar receiver, text drags and removal-Off behavior retain their existing paths.

Only Copy is offered. The source uses standard OLE cursors and [IDropSource rules](https://learn.microsoft.com/en-us/windows/win32/api/oleidl/nf-oleidl-idropsource-querycontinuedrag): hold the left button to continue, release to drop, Escape or shelf/session cancellation to cancel. Self-drop is rejected while the native drag runs. Shelf removal still requires a successful async EndOperation, the current feature/session lifetime and exact original shelf identities. Cancel, errors or missing confirmation retain entries. No original file is moved or deleted. A destination may retain its adapter until native work completes even if Vela's confirmation wait expires.

This changes the outgoing mouse path. Touch/pen, the drag-image appearance and behavior in arbitrary third-party targets have not been established. Standard cursor handling does not establish a full physical drag pass.
