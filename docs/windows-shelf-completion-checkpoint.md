After Esc dismissed the duplicate-file dialog and a 30-second wait, the user reported **“both entries disappeared.”** Independent hashes verify both source files and both old destination files stayed unchanged. ## Candidate change

File drags now install an IDataObject adapter with an independent, identical file package and an explicit IDataObjectAsyncCapability interface. A separate package avoids recursive reads through the original package. Native file payload and order survive the round trip.

The adapter tracks the source's async operation. Automatic removal requires exactly one start and an EndOperation callback with **S_OK and Copy**. Logical/performed drop-effect messages are diagnostic only. Failed/canceled HRESULTs, S_FALSE, Move, Link, combined effects, missing starts and invalid sequences retain entries. No callback within 30 seconds also retains entries. The existing shelf/session lifetime tokens and exact-entry identity still guard late completion. Text transfers keep their existing behavior.

The adapter remains available to the destination if the window closes or confirmation times out; it does not forcibly release the inner COM object while a target might still use it. No original file is moved or deleted. Diagnostics contain only callback/effect values and are written inside explicit validation profiles. See Microsoft's [async Shell transfer protocol](https://learn.microsoft.com/en-us/windows/win32/shell/datascenarios#dragging-and-dropping-shell-objects-asynchronously) and [EndOperation contract](https://learn.microsoft.com/en-us/windows/win32/api/shldisp/nf-shldisp-idataobjectasynccapability-endoperation). Successful native callback tests are not proof that every destination implements that contract or that a partially skipped Explorer operation reports a failed HRESULT.

The user reported that both entries stayed after canceling the duplicate dialog; source and old destination hashes remained unchanged. In the fresh-destination test, both copied files match their originals byte for byte. Although the user said the transfer worked, agent inspection found two retained shelf rows and the informational message that completion was unconfirmed. The native trace contains StartOperation and Copy effects, but no EndOperation. This establishes successful copying and failed automatic removal through the WinUI bridge. The candidate then exited normally through Settings. The next candidate sends the tracked object directly through native OLE; partial/skip and its positive/negative physical behavior require their own tests.
