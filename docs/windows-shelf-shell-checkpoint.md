## Reproduced problem and correction

The user reported that `28775fed` dragged awkwardly and kept entries after successful copying. Both generated destination files match the originals. The trace establishes that successful copying used the WinUI fallback; experimental native mouse drags repeatedly returned None and left one loop active until automated Escape. The failed resident exited normally through Settings.

A new fixture reproduced the completion failure directly through Windows' folder IDropTarget, without injecting a mouse drag: both files copied, but the original filesystem payload never delivered final EndOperation. Filtering that payload to CF_HDROP still failed confirmation. Offering file descriptors and streams instead produced a real final callback. This evidence replaces the earlier hypothesis that bypassing WinUI alone would solve completion.

The shelf now leaves pointer capture, extended selection and drag images to WinUI. With automatic removal On, regular filesystem files offer native FILEGROUPDESCRIPTORW/FILECONTENTS streams and preferred Copy through the existing tracked IDataObject. A successful S_OK EndOperation with exactly Copy is still required before removing the original shelf references. Cancel, partial skip, failure, missing confirmation and late session cancellation retain entries. Text, removal-Off, incoming drops and the accepted taskbar receiver retain their paths. Folder/mixed-folder and pathless provider cases keep their existing payload and may remain unconfirmed; this checkpoint does not establish automatic folder removal or universal destination compatibility.

WinRT's virtual descriptors initially made copies ReadOnly/Temporary. The wrapper clones descriptor memory and preserves each source's ReadOnly/Hidden/System/Archive bits, using Normal when none apply. This passes the direct folder-handler tests, including read-only originals. Physical WinUI dragging subsequently exposed an additional read-only access wrapper: both writable originals copied as ReadOnly/Archive. The child checkpoint corrects that separate serialization path. User originals are not modified. Transfer-format diagnostics are bounded to 128 distinct entries per transfer inside validation profiles, avoiding repeated hover logging. The experimental OLE mouse source and threshold code were removed.
