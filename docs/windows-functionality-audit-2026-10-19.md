## Important measured results

- **Keep awake:** explicit Start and Stop work. The one-minute request was active at **54.219 seconds**, then Off/Stop disabled by **80.764 seconds**. This is an observation bracket, not a claim that release happened at exactly 60 seconds. AC/app/display/suspend behavior is still open.
- **Internet speed:** a real Cloudflare run returned **297.0 Mbps down, 33.4 Mbps up, 57 ms HTTP latency**, with **64 MB received and 16 MB of generated data uploaded**. The second run canceled during latency and re-enabled Start. One sample is not a calibrated network benchmark.
- **Developer feeds:** one local RSS, one Atom and one HTTP 503 fixture produced two sorted headlines from 2/3 sources. The failure named its source; local filtering worked. The fixture received only `/rss`, `/atom`, `/broken`, with no article request or background repeat.
- **Workspace:** capture saved two visible window records. Vela then exited; the private fixture was reduced to exactly one Notepad record before any restore. Restore moved one window/zero unavailable; Undo restored its prior position. Native capture dimensions changed **695×371 → 951×540**. The exact generated text remained **Unmodified**, and no other app was repositioned.
- **Microphone:** the opt-in test requires exactly one initially unmuted active endpoint, observes Mute all and Unmute all, and restores the original endpoint by captured identity in `finally`. This laptop passed. No sound was recorded or played. Multiple endpoints, hot-plug and failure paths are not established.
- **Downloads:** generated-file checks reject a changed reviewed file and a sibling-prefix/out-of-root selection, preserve both byte sequences and stop a pre-canceled scan. **Zero files were recycled**.
- **Native media:** the final run repeats actual decodable outputs, original-byte preservation, alpha/watermarks/offline English OCR, MP4/M4A caps, impossible limits, mixed failures and active encoder cancellation. Representative MP4 is **3,278,934 bytes under 3,489,845**; M4A is **195,442 bytes under 218,571**, non-silent 48 kHz stereo with 12.011 s duration. GIF tests decode changing frames/timing/loop metadata. These are backend results, not completed picker-driven batches.

## Limits that remain material

Seven physical-input features need real wheel/buttons/Caps/close-key events. `InputService` intentionally passes through injected keyboard and mouse events; spoofing its internal snippet replay marker would not test real input. Core snippet/close/session logic is covered, but this does not establish wheel smoothing, horizontal inversion, button interception or physical debounce. Keyboard cleaning is exceptional: its lock check intentionally runs before the injected-event pass-through and its Start/Stop was observed.

The [Computer Use skill](C:/Users/Admin/.codex/plugins/cache/openai-bundled/computer-use/26.1013.40934/skills/computer-use/SKILL.md) requires its [guidance](C:/Users/Admin/.codex/plugins/cache/openai-bundled/computer-use/26.1013.40934/docs/guidance.md), which says: **“Do not use the Windows key or shortcuts involving the Windows key.”** Super-key hold behavior therefore also needs physical testing. Its [confirmation policy](C:/Users/Admin/.codex/plugins/cache/openai-bundled/computer-use/26.1013.40934/docs/confirmations.md) places local UI deletion under **“Always Confirm at Action-Time (Even If Pre-Approved)”**. Actual Recycle Bin removal was left open while the user is away; the non-deleting backend safeguards were tested instead. No permission question is pending.

The transport does not expose PickerHost as a targetable window and rejects cross-window drag endpoints outside source-window bounds. Earlier attempts document those limits in [the dated UI checkpoint](windows-ui-checkpoint-2026-10-19.md). The audit did not replace native pickers with hidden UI Automation or direct service calls labeled as UI tests. Full selection/save/conversion flows, real outgoing shelf drags and actual pin windows remain unverified.

Clipboard auto-clear lock/suspend/expiry and fresh cross-app paste/snippet publication were not exercised. The separate disposable global-publication fixture was not run; private data-package snapshots and deterministic ownership/race tests passed. Before and after the entire tour, clipboard metadata was **empty, sequence 36**, proving no intervening clipboard write by this audit. Earlier VM text/HTML results are historical.

Broader accessibility/Narrator, high contrast, mixed DPI, HDR, multi-display/device changes, elevated/custom/IME editors, real notification delivery/quiet-time, lock/suspend/shutdown in-flight cancellation, long/DRM/multichannel/unusual codecs and target-desktop hardware remain open.
